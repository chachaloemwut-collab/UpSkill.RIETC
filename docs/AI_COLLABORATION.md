# มาตรฐานกลาง Antigravity / DeepSeek / ChatGPT

ใช้ร่วมกับ `AGENTS.md` และกติกาในโฟลเดอร์ย่อย ไม่แทนที่คำสั่งผู้ใช้หรือข้อจำกัดของแต่ละโปรแกรม
Git เป็นที่เก็บรุ่นและหลักฐาน ไม่ใช่ผู้ปฏิบัติงานตัวที่สี่

## เริ่มทุกงานและรับช่วงทุกครั้ง

1. อ่าน `AGENTS.md`, เอกสารนี้, `docs/AI_HANDOFF.md` และคำสั่งผู้ใช้ล่าสุด
2. ตรวจเวลาเครื่องจริง, `git status --short --branch`, commit และสถานะ PR/CI ที่เกี่ยวข้อง
3. รัน `python3 scripts/agent-work.py status` ก่อนแก้ไฟล์หรือสั่ง deploy
4. จองงานด้วย `python3 scripts/agent-work.py start --owner chatgpt --task "คำอธิบายงานและขอบเขต"` (เปลี่ยน owner เป็น `antigravity` หรือ `deepseek` ตามโปรแกรม)
5. เก็บ token ที่คำสั่งคืนไว้เฉพาะงานนี้ หากมีเจ้าของอยู่แล้ว อ่านอย่างเดียวและรอส่งต่อ ห้ามหยิบ token ของงานอื่นมาใช้

## เวลาและความเป็นเจ้าของ

- เก็บเวลาจริงแบบ ISO 8601 UTC; รายงานผู้ใช้เป็น Asia/Bangkok (UTC+7) พร้อมวันที่
- บันทึก started_at, heartbeat_at และ finished_at ผ่านเครื่องมือ พร้อม commit/หลักฐานในบันทึกส่งต่อ
- ระหว่างทำงาน อัปเดตทุก 10 นาทีด้วย `python3 scripts/agent-work.py heartbeat --token TOKEN`
- เกิน 30 นาทีจะแสดง stale แต่ไม่ปลดสิทธิ์อัตโนมัติ: ตรวจว่าเจ้าของยังทำงานหรือมีไฟล์ไม่ commit ก่อนติดต่อให้ส่งต่อ ถ้าเจ้าของหายต้องให้ผู้ใช้ตัดสินใจ ไม่ลบสถานะเอง
- เวลาใหม่กว่าไม่ได้หมายถึงโค้ดถูกกว่า และไม่อนุญาตให้ทับงานเก่า ใช้ commit, PR และหลักฐานการทดสอบประกอบ
- checkout เดียวมีผู้เขียนได้หนึ่งงานในแต่ละเวลา รวมทั้งการเปลี่ยน branch/staging/commit ห้ามเปลี่ยน branch ใต้โปรแกรมอื่น
- สิทธิ์นี้ใช้ร่วมกันระหว่าง Git worktrees ที่มี git-common-dir เดียวกันบนเครื่องเดียว เป็นกติกาแบบร่วมมือ ไม่ได้บล็อกโปรแกรมที่ข้ามคำสั่งนี้
- ต่างเครื่อง/ต่าง clone ต้องมีผู้ประสานงานเดียวและเจ้าของงานใน Draft PR ก่อนเขียน ห้ามอ้างว่าตัวจองบนเครื่องนี้ป้องกันทั้งทีมทั่วโลก

## ส่งต่อและจบงาน

อัปเดต `docs/AI_HANDOFF.md` แบบเพิ่มรายการ ไม่ลบประวัติ ใส่เวลา, โปรแกรม, งาน, branch/commit,
ไฟล์ที่แก้, ผลตรวจจริง, สิ่งที่ยังไม่ตรวจ, ข้อจำกัด และขั้นตอนต่อไป ห้ามบันทึกรหัสผ่าน/token/ข้อมูลส่วนบุคคล
จากนั้น `python3 scripts/agent-work.py finish --token TOKEN --note "ผลตรวจและงานที่เหลือ"`
ก่อนตอบจบแชตหรือส่งงานให้โปรแกรมอื่นต้องปล่อยสิทธิ์ พร้อมระบุไฟล์ที่ยังไม่ commit
งานค้างให้เขียน blocked พร้อมสาเหตุใน note แล้วส่งต่อ ห้ามถือสิทธิ์ทิ้งไว้โดยไม่มีเจ้าของติดตาม

## กติกา production และบัญชีผู้ดูแล

- deploy ผ่าน workflow/manifest ของ Jasmine ที่ตกลงไว้เท่านั้น ตรวจ CI, commit และ digest ให้ตรงกัน
- build/publish ผ่าน ไม่เท่ากับ production deploy ผ่าน ต้องอ่านสถานะ release บนเซิร์ฟเวอร์และ health จริง
- service ที่หยุดไว้ต้องตรวจเหตุผลและบันทึกส่งต่อก่อนเปิด ห้ามสรุปว่าเสียจากการเดา
- ห้ามเปลี่ยน password hash, role, status หรือ revoke session ของบัญชีผู้ดูแลผ่าน seed/startup/migration/deploy
- รหัสผ่านใน environment ใช้สร้างบัญชีเริ่มแรกเมื่อยังไม่มีบัญชีเท่านั้น ห้าม sync ทับบัญชีเดิม
- การกู้บัญชีเป็นงานแยกที่ผู้ใช้สั่งชัดเจน และต้องตรวจผลแยกจาก deploy
- ห้ามแตะเว็บ ฐานข้อมูล network หรือบริการอื่นนอกขอบเขตงาน

## การเริ่มใช้ในแชตที่เปิดค้าง

ไฟล์กติกาไม่ได้รับประกันว่าแชตเก่าจะอ่านใหม่ ให้แต่ละโปรแกรมอ่านเอกสารนี้และรายงานเวลา/commit/
สถานะ lease ก่อนเริ่มงานครั้งถัดไป ถ้าโปรแกรมไม่อ่าน instructions อัตโนมัติ ให้แนบ `AGENTS.md` และเอกสารนี้ในแชต
ห้ามตอบว่าโปรแกรมอื่นรับทราบแล้วจนเห็นการยืนยันจริง
